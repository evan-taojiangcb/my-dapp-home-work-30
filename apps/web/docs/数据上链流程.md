## 核心思路

**不调用智能合约**，而是把文本作为 **calldata**（`tx.input`）写入一笔普通 ETH 交易。Calldata 随交易永久存储在区块链上。

---

## 完整流程

```
用户输入文本
    │
    ▼
① 实时 Hex 预览（纯前端）
    toHex(text) → "0x48656c6c6f..."
    publicClient.estimateGas() → 预估手续费
    │
    ├─ 用户点击「发送附言到区块链」
    ▼
② 文本编码
    toHex(text.slice(0, 500))  →  0x 开头的 hex 字符串
    这串 hex 就是交易的 data 字段（calldata）
    │
    ▼
③ 触发 MetaMask 签名弹窗
    sendTransactionAsync({
      to:    0x000...dEaD,   // burn address（黑洞）
      value: 0n,             // 不转 ETH，只付 gas
      data:  hex字符串,       // ← 你的文字就在这里
    })
    status: idle → sending
    │
    ▼
④ MetaMask 用私钥给交易签名
    签名完成 → 广播到以太坊节点（Sepolia / Hardhat）
    返回 txHash
    status: sending → confirming
    │
    ▼
⑤ 等待区块打包（useWaitForTransactionReceipt）
    轮询/监听直到交易被矿工打包进区块
    receipt.status === "success"
    │
    ▼
⑥ 链上回显读取
    publicClient.getTransaction({ hash: txHash })
    → tx.input 就是当时发送的 calldata（hex）
    hexToString(tx.input) → 还原为 UTF-8 文本
    status: confirming → success
```

---

## 关键设计点

| 问题 | 答案 |
|------|------|
| 数据存在哪？| 存在交易的 `input`（calldata）字段，不在合约 storage |
| 为何发给 burn address？| `from == to` 且带 data 时，部分节点/MetaMask 会拒绝；burn address 是公认的"黑洞"，任何节点都接受 |
| 会损失 ETH 吗？| 不会，`value = 0n`，只消耗 gas 费 |
| 数据永久吗？| 是，calldata 随区块永久记录在链上，无法删除 |
| 为何不用智能合约？| 更简单，无需部署合约；calldata 本身就是链上存储手段 |
